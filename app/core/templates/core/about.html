About the project

About WhatWebSees

WhatWebSees is an independently developed public project that makes web, browser and network diagnostics easier to inspect and understand.

Why it was built

Websites receive connection details, request headers and browser-reported values that are often invisible to the person browsing. WhatWebSees was built to make those signals visible, then place them beside practical tools for checking DNS, HTTP behavior, TLS certificates, redirects and related network concepts.

The project favors a useful result with a plain-language explanation over a score that hides assumptions. When a value is an estimate, a browser claim or a single point-in-time observation, the page should say so.

Privacy-first by design

Tools that can work entirely in the browser do so. Screen and viewport checks, file hashing, password-strength checks, URL parsing and several browser diagnostics process their working values locally. Some browser pages request a small, allowlisted set of headers that the browser already sent to WhatWebSees so the page can compare browser and server observations.

Network tools need server-side processing because a browser cannot safely or consistently perform arbitrary DNS, TLS and HTTP diagnostics. Values submitted to those tools are processed by the WhatWebSees server for the requested lookup. Server-side URL fetches are restricted to public HTTP or HTTPS destinations and re-check redirects to protect internal addresses. The speed test transfers bounded temporary data between the browser and WhatWebSees infrastructure on Cloudflare; upload bytes are counted and discarded.

Diagnostic results are not saved by the application. Normal hosting and security infrastructure may still process request metadata needed to deliver and protect the service. Optional analytics is separate and loads only after consent.

Data sources and honest limits

The IP lookup uses a locally maintained copy of the DB-IP City Lite database for approximate geographic fields. The submitted address is not sent to an outside geolocation API. City Lite does not provide this project with ASN, ISP or organization fields, and an IP result is never presented as a home address, a person or GPS location. Pages link to the specifications, vendor documentation or technical references that are most useful for checking factual claims.

Browser values can be reduced or spoofed. DNS answers can be cached or geographically steered. HTTP, certificate and speed results describe one route and one moment. WhatWebSees communicates those limits instead of treating every available field as certain.

Public source code and project owner

WhatWebSees is developed by Jakub Lejk. You can inspect the implementation, report an issue or follow the project through the public repository.
