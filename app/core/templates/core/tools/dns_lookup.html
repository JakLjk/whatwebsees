DNS lookup is not a website availability test

A valid DNS answer only shows that records were returned. It does not prove that a web server accepts a connection, presents a valid TLS certificate or returns a successful HTTP response. Use the Website Status Checker when you need to test the web service itself; use the Internet Speed Test when the question is about the browser's connection rather than one domain's records. Automation can request the six supported record types through the Developer DNS API.

TTL, caching and changes

TTL means time to live: the number of seconds a resolver may cache an answer before asking again. When a record changes, resolvers with an older cached answer can keep returning it until that TTL expires. Different users can therefore see the old and new values at the same time; traffic steering and resolver policy can create additional differences even after caches refresh.

Authoritative servers and recursive resolvers

An authoritative server publishes records for a zone. A recursive resolver accepts a client's question, follows the DNS hierarchy when needed, caches the answer and returns it to the client. This tool shows the answer available through its resolver at lookup time rather than querying every authoritative server from every location.

Use DNSSEC Checker to inspect signing and delegation records, Email DNS Checker for MX, SPF, DKIM and DMARC, Hostname Lookup for only public A and AAAA results, or Reverse DNS Lookup to find PTR names for an address. For registration context, compare the domain's RDAP data and registry-based age estimate.
