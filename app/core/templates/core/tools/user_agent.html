Understanding a User Agent check

A User-Agent is a browser-provided string sent with many web requests and available to scripts as navigator.userAgent. The readable result above is a best-effort interpretation of that raw value and, where supported, structured Client Hints. It is a browser claim rather than verified hardware identity.

How to read the major components

Example componentWhat it generally represents
Mozilla/5.0A long-standing compatibility token, not evidence that the browser is Firefox.
Parenthesized platform commentReported operating-system family, architecture or mobile hints; details may be frozen or reduced.
AppleWebKit or GeckoRendering-engine lineage or compatibility information.
Chrome/…, Firefox/…, Version/… or Edg/…Tokens used to infer browser family and a reported version.
Safari/…, like Gecko and similar textCompatibility tokens that may coexist with another browser's identifying token.

Why so many strings start with Mozilla/5.0

Early websites sometimes served features only to browsers they recognized as Mozilla-compatible. Other browsers adopted the same prefix to receive working content, and it became a historical compatibility convention. Modern identification depends on the combination and order of tokens, not that prefix alone.

Browser, version and platform interpretation

The checker looks for more specific product tokens before generic compatibility tokens: for example, Edge and Opera strings also contain Chrome-like text. A version is the value the browser reports, which may expose only a major release. The operating-system label describes the reported platform family; it does not verify an edition, patch level, installation or physical device.

What cannot be reliably inferred

A User-Agent cannot reliably establish a person, exact device model, installed updates, hardware capabilities or whether every named feature is present. Bots, privacy browsers, extensions and developer tools can reduce or spoof it, while compatibility tokens can name products that are not actually running.

User-Agent reduction and Client Hints

Supporting browsers reduce the passive detail in the traditional string by freezing or coarsening values such as minor browser versions, operating-system versions and device models. User-Agent Client Hints provide selected structured values such as brands, platform and mobile status. Higher-entropy hints require an explicit request and may be unavailable or declined; they are not a way to bypass privacy choices.

For developers: test features, not browser names

When code needs a web capability, feature detection is usually more dependable than UA sniffing: test whether the required API, property or CSS value exists, then provide a fallback. Browser-name branches become stale and can misclassify spoofed, reduced or newly released browsers.

Compare the interpretation with the broader Browser Checker, review preference signals in the Privacy Check, or see what reached the origin in the HTTP Headers Checker. The Canvas Fingerprint Test and WebGL Checker explain two other browser-exposed surfaces without treating any one value as identity proof.
