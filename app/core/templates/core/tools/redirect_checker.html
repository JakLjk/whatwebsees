The Location header and each hop

An HTTP redirect response normally supplies a Location header containing the next target. That target can be absolute or relative to the current URL. A redirect chain is the sequence of requests created when one target redirects again; each extra hop adds another response round trip before the final content can load.

When redirect chains become a problem

One intentional redirect, such as HTTP to HTTPS, is common. Unnecessary hops add latency and create more places for cache or configuration mistakes. A redirect loop occurs when targets eventually point back to a URL already in the chain, so no final resource can load. The checker follows a bounded number of public targets and reports each completed hop.

Canonical host and HTTPS examples

A site may redirect http://example.com/page to https://example.com/page so the browser continues over HTTPS. It may also choose one canonical hostname, such as redirecting https://www.example.com/ to the apex https://example.com/—or the reverse. Combining both choices into one hop is usually cleaner than sending the client through separate scheme and hostname redirects.

When method preservation matters

For an ordinary GET page, method differences are rarely visible. For a POST upload, PUT update or API request, changing the method to GET can discard the request body and change the operation. Use 307 or 308 when the destination must receive the original method and body; 303 deliberately directs the client to retrieve a separate result with GET.

Practical result patterns

  • 301 → 200: a straightforward permanent page move.
  • 301 → 301 → 200: a working chain with a potentially removable hop.
  • 303 → 200 after POST: a common form-submission result flow.
  • 307 → 200: a temporary move that keeps the original method.

Technical safety

Every destination is checked again before the server follows it. Credentials, non-standard ports and hostnames that resolve to non-public addresses are refused.

After tracing a chain, check the final website status, inspect its response headers and browser security policies, verify the TLS certificate, or review the final page with the Meta Tags Checker. The longer HTTP redirects guide covers related edge cases.
