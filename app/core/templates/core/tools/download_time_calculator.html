How Internet speed and download time relate

The calculator converts file bytes to bits, then divides by the selected bits-per-second rate. Network speeds are normally advertised in bits, while file sizes and browser download rates are often shown in bytes. Because eight bits make one byte, 100 Mbps has an ideal ceiling of 12.5 MB/s before overhead.

Mbps, MB/s and file-size units

The lowercase b in Mbps means bits; the uppercase B in MB/s means bytes. Divide Mbps by eight for the ideal MB/s rate. File units can also use different bases: decimal MB and GB use powers of 1,000, while binary MiB and GiB use powers of 1,024. This calculator uses decimal units, so 1 GB is 1,000 MB; a 1 GiB file is about 1.074 GB.

Why this result can differ from another speed test

A speed test measures a particular path at a particular time. Another service may use a different server or edge location, Internet route, test duration, payload size, number of parallel connections or calculation method. Local conditions matter too: Wi-Fi interference, a VPN, network congestion, background traffic, and browser or device performance can each become the bottleneck.

Why very small downloads can underestimate fast connections

A short transfer spends a larger share of its time establishing the connection, waiting for request latency and increasing the transport rate. It can finish before a fast connection has enough sustained data to demonstrate its capacity. This test steps through larger payloads and parallel streams, within its published limits, rather than estimating a high-speed link from one tiny file.

HTTP latency is not ICMP ping

The latency shown here times an HTTP request and response to the WhatWebSees Cloudflare service. It includes the web protocol and connection path the browser actually uses. An ICMP ping uses a different protocol, may take another network path or priority, and can be blocked or rate-limited independently, so the two measurements need not match.

Download throughput versus upload throughput

Download throughput is the rate at which the browser receives bytes; it affects downloads and streaming. Upload throughput is the rate at which the browser sends bytes; it matters for backups, file sharing and outgoing video calls. Many access plans are asymmetric, so a much lower upload result can be normal for the plan even when the connection is healthy.

How to get a more reliable speed-test result

  • Pause large downloads, backups and streaming on this device and others sharing the connection.
  • Use Ethernet when the goal is to test ISP capacity rather than Wi-Fi performance.
  • Repeat the test and compare several completed runs instead of relying on one snapshot.
  • Test at different times if you suspect peak-hour congestion.
  • When using Wi-Fi, note signal strength, band, interference and distance from the access point.

If a site feels slow despite a reasonable connection result, check its HTTP status and response time, inspect its DNS records, or use the Browser Checker to review the current browsing environment. The network and web glossary defines Mbps, latency, DNS and related terms.

Technical details and transfer limits

The browser discards the first latency request as a warm-up and reports the median of four later requests. Download stages fetch incompressible Cloudflare static assets using parallel streams when needed; throughput is based on actual bytes received over the stage's wall-clock body-transfer time. Upload stages send temporary browser-generated bytes to a Worker that counts and discards them.

The complete test is capped at 154 MiB downloaded, 54 MiB uploaded and 35 seconds. Each response must identify the expected Cloudflare backend, and incomplete transfers are rejected rather than reported as a speed result.
